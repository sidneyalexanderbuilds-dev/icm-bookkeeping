How It Works

Five stages. Four judge gates.

Each stage has one job. After each job, the LLM judges its own output and scores confidence. If confidence is low, it asks a binary question before proceeding.

1

Collect — Normalize invoices from any source

Drop PDFs, images, or emails into input/invoices/. The collect stage extracts raw text and normalizes to JSONL. No judge here — pass-through only.

2

Extract + Judge — Structured field extraction

LLM extracts vendor, amount, date, line items, payment terms, invoice number. Judge scores on vendor resolution, amount accuracy, and completeness. "Is this Amazon or AWS?"

3

Categorize + Judge — Map to chart of accounts

LLM maps to account codes (Software/SaaS, Meals, Travel, etc.). Judge scores category accuracy, duplicate detection, and anomaly flags. Learned rules applied first.

4

Journal + Judge — Double-entry generation

LLM generates debit/credit pairs that balance. Judge verifies: debits = credits? right accounts debited/credited? memo accurate? Software/SaaS DEBIT, Cash CREDIT

5

Export + Validate — Mechanical checks only

No LLM needed here — just math. Balance check (debits = credits), format validation, completeness check. Outputs journal_export.csv for spreadsheet import.

The Judge Gate

After every stage, the LLM critiques its own output and scores confidence 0–1. Four possible routes:

Score Decision What happens
≥ 0.85 PROCEED High confidence. Next stage immediately.
0.60 – 0.84 CLARIFY Ask binary question → learn rule → retry (max 2×). Then MISC.
0.40 – 0.59 MISC Default to Miscellaneous (Expense or Income by sign). Continue pipeline, flag for review.
< 0.40 FLAG Block. Await human review. Pipeline resumes after human resolves.
The Learning Loop

The system gets smarter over time

Every binary clarification isn't just a one-off answer. It's a learned rule. The next invoice from the same vendor uses it. Fewer clarifications. Higher pass-through.

Client answers binary question:
  "Is this Amazon or AWS?" → [Amazon]

  System infers and writes rule:
  vendor_map.csv  ← AWS → Amazon, AMZN → Amazon
  category_hints.json ← Amazon → Software/SaaS

  Next invoice from AWS:
    1. Rule found → category resolved immediately
    2. Confidence: 0.92 → PROCEED (no question asked)
    3. Pipeline continues, human not involved

Getting Started

Up and running in five minutes

The pipeline is a Python script. Set your LLM provider, scaffold a workspace, drop in invoices.

# 1. Clone the repo

git clone https://github.com/sidneyalexanderbuilds-dev/icm-bookkeeping.git

# 2. Set your LLM provider (OpenAI by default)

Set ICM_LLM_PROVIDER and ICM_LLM_MODEL in your environment, or edit scripts/run_pipeline.py. Supports OpenAI, Anthropic, and local (llama.cpp/Ollama).

# 3. Scaffold a client workspace

python scripts/scaffold.py --template . --workspace ~/.bookkeeping/myclient --client "My Business"

# 4. Configure your chart of accounts

Edit _config/rules/chart_of_accounts.json with your account codes and categories.

# 5. Drop invoices in and run

cp invoice.pdf input/invoices/ && python scripts/run_pipeline.py --workspace ~/.bookkeeping/myclient --watch

ℹ️
Prerequisites: Python 3.10+, pdftotext (poppler-utils), tesseract for OCR on image files. The pipeline will tell you what's missing.

For text extraction from PDFs and images, the system uses pdftotext (PDF) and tesseract (images). Both are standard Linux tools installable via apt install poppler-utils tesseract-ocr.
